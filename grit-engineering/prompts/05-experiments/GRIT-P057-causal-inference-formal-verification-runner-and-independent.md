# GRIT-P057: Causal inference, formal verification runner and independent audit verification

| Group | Phase | Wave | Complexity | Resources | Review |
|---|---|---|---|---|---|

## Prompt identifier

`GRIT-P057`

## Objective

Add effect estimators (regression adjustment, IPW, AIPW with bootstrap CIs), a sandboxed runner for external proof checkers, and `grit-verify audit verify`, which checks the audit chain from files alone.

## Scientific context

Audit verification must be independent of the writer: it reads docs/specifications/audit-format.md, not grit_lab code.

## Prerequisites

- `GRIT-P055` Statistical validation, calibration evaluation and replication (must be `done`)
- `GRIT-P012` Graph primitives and causal DAG tools (must be `done`)
- `GRIT-P050` Hash-chained audit log (must be `done`)

Files from prerequisites that must exist:

- `docs/specifications/audit-format.md`

## Existing repository context

Read before changing anything:

- `AGENTS.md`
- `prompts/status.json` (once GRIT-P006 is done)
- `docs/specifications/audit-format.md`
- Hernán & Robins (2020) Causal Inference: What If

## Scope

- `causal_inference.py`.
- `formal_verification.py`: `run_checker(argv, inputs, timeout)` subprocess without shell, scrubbed env.
- `audit.py` + `cli.py`: `grit-verify audit verify PATH` reports first bad event; `grit-verify signature verify FILE`.

## Out of scope

- Writing audit events (grit_lab does that).

## Architecture constraints

- `grit_verify` imports only `grit_core`, the standard library, numpy, scipy and `cryptography` (ADR-0008).
- Never import or call code from `grit_lab`, `alphalytica`, `grit_data` or any L2 package.
- Evaluation logic must not be configurable by the evaluated model or its training process.
- Follow AGENTS.md. Add no dependency the prompt doesn't name.
- No `eval`, `exec`, `pickle.load`, unsafe YAML, `shell=True`, or unnormalized user paths.

## Failure handling

- A prerequisite isn't `done` in `prompts/status.json`, or a file listed under Prerequisites is missing: stop, set this prompt to `blocked`, report what's missing.
- A test fails for a reason inside this prompt's scope: fix the code, not the test. Never delete, skip or weaken a test to get green.
- A test fails for a reason outside this scope (another package's bug, environment issue): record it under Unresolved issues with the failing output; don't patch other packages.
- A scientific assumption, constant or reference value in this prompt looks wrong: don't change it silently. Implement as specified, flag it in the report, and propose the correction.
- The work needs a dependency, file or permission not listed here: stop and ask, with the reason.
- Verification commands can't run in your environment: say so explicitly; never report them as passed.
